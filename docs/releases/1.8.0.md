# EasyPOS 1.8.0

This release brings the redesigned mobile workflow and a clearer route from product entry to checkout. The project website and user guide now show the current EasyPOS design and explain installation, first use, stock, barcodes, backups, and updates.

## Highlights

- **Mobile catalogue:** pair a phone on the same Wi-Fi, photograph a barcode, and create or edit a product with a photo, category, price, and quantity.
- **Mobile checkout:** browse product photos, filter by category, add items to a cart, choose a customer and payment method, and confirm a paid sale. The server calculates prices from the database and uses the existing stock-decrement logic.
- **Desktop polish:** updated EasyPOS logo and window icon, a more accessible cart in the header, and improvements to navigation, themes, and catalogue controls.
- **Documentation:** a redesigned [project website](https://frnaky-op.github.io/EasyPOS/) and a new [illustrated user guide](https://frnaky-op.github.io/EasyPOS/guide.html).

## Install or update

Download `EasyPOS-Setup-1.8.0-x64.exe` from this release. Installed NSIS copies can also check **Paramètres → Mises à jour** and install the new version when the download finishes. Back up the shop data before upgrading.

If your current installation uses the older Forge/Squirrel installer, install this NSIS version manually once. The internal `PharmaSpot` data directory is unchanged, but a backup is recommended before changing installers.

## Mobile requirements

The PC and phone must use the same trusted Wi-Fi. EasyPOS serves the phone interface on local port 3211 and shows a temporary eight-digit pairing code in **Accès mobile**. The local HTTP connection is not encrypted. Barcode scanning uses a photo from the phone camera; continuous live video scanning is not provided on this local HTTP address.

## Source and verification

The release workflow verifies that the tag matches `package.json`, installs dependencies with Node.js 22, runs the automated tests, and builds the Windows installer and `latest.yml` together. Only the assets from this version's workflow are intended for the in-app updater.
